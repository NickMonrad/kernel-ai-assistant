# Play permission declarations — versionCode 2

This audit describes the release manifest and user-triggered paths. It is declaration text for Play review, not a claim that Play has approved a permission. Reviewer recordings should show the described user-visible trigger, system access flow, and resulting feature behavior without exposing unrelated personal data.

## Foreground services

| Manifest service / type | What starts it and why | Play declaration text | Reviewer video should show |
|---|---|---|---|
| `androidx.work.impl.foreground.SystemForegroundService` — `dataSync` | WorkManager foreground work during user-requested model downloads; displays download progress and keeps the transfer visible. | “Jandal downloads the on-device AI model selected by the user. A foreground notification shows download progress while the user-requested transfer runs; the service stops when the transfer completes or is cancelled.” | Open model setup, start a model download, show its progress notification, then show completion/cancellation and notification removal. |
| `com.google.android.play.core.assetpacks.ExtractionForegroundService` — `dataSync` (disabled by default) | Play Core starts it only for foreground asset-pack extraction/download. It is dependency-owned and not started by Jandal's user-facing workflows in this release. | “If an on-demand Play asset pack is being extracted, Play Core uses a foreground service to complete that user-requested delivery.” | If asset-pack delivery is active in the review build, request the pack and show its progress/completion; otherwise verify it remains disabled and absent from active foreground-service use. |
| `InferenceLoadingService` — `specialUse` | `LiteRtInferenceEngine` starts it around local model initialization to keep the app process important while GPU/model initialization runs. No standard FGS type represents local model initialization. | “Jandal initializes a user-selected on-device language model for local inference. This short-lived foreground service keeps the app process available during model initialization and stops after initialization completes or fails; no model inference is sent to a cloud LLM.” | Open a conversation requiring a model, show initialization/ready state and the foreground notification, then show notification removal after load/failure. |
| `InferenceGenerationService` — `specialUse` | Started during local response generation to keep the process alive while the on-device model produces a response. No standard FGS type describes local AI generation. | “Jandal runs the user-requested language-model response locally on the device. The foreground service maintains process priority while generation is active and stops when generation completes or is cancelled.” | Send a prompt, show the generation notification while the model is responding, then show response completion/cancellation and notification removal. |
| `.alarm.ClockAlertService` — `mediaPlayback` | Started by the scheduled clock alarm/timer receiver to play the user's selected alert sound and maintain a high-priority, ongoing ringing notification with Stop and Snooze actions. While ringing it publishes an active media session and MediaStyle notification so Android 14+ treats the ongoing foreground notification as media playback rather than a swipe-dismissable generic FGS notice. The notification body opens the ringing activity; when Jandal is visible as the alert fires, the service opens that activity immediately. Timer Snooze schedules one new 10-minute timer in release builds (10 seconds in debug builds). | “When a user-created alarm or timer expires, Jandal plays its alert sound and presents an ongoing alarm-category notification with Stop and Snooze controls. The service ends when the alert is stopped or snoozed.” | Create a short timer, show its ringing notification and actions, invoke Stop and verify notification removal and alert sound/vibration stop. |
| `.assistant.WakeWordService` — `microphone` | Starts only after the user enables “Hey Jandal” and microphone access is granted; listens locally for the wake phrase. | “When the user explicitly enables Hey Jandal and grants microphone access, Jandal listens for the wake phrase to begin voice interaction. The persistent notification indicates listening; disabling the feature stops microphone use and the service.” | Enable Hey Jandal from Voice settings, show the microphone/listening notification and wake interaction, then disable it and show the service/notification stop. |

The two inference services remain `specialUse` because `dataSync`, `mediaPlayback`, `microphone`, and `shortService` do not describe model initialization or on-device inference generation. Their subtype descriptions belong on the individual service declarations.

Other merged services have no `foregroundServiceType` and are not foreground services: the app's `VoiceCommandService`, `JandalRecognitionService` stub, and Play Core `AssetPackExtractionService` (also disabled by default).

## Sensitive permissions and special access

| Permission / access | Feature, trigger, and justification | Play declaration text / reviewer evidence |
|---|---|---|
| `SCHEDULE_EXACT_ALARM` | Clock alarms, timers, list due reminders, and important-date reminders are scheduled only after the user creates/enables the corresponding item. Exact access is optional. When unavailable, clock alarms/timers are scheduled inexactly and the user must be told timing may be less exact; an in-app path should offer `ACTION_REQUEST_SCHEDULE_EXACT_ALARM`. | “Users create alarms, timers, and reminders and choose their trigger time. Exact access improves timing but is optional; without it, Jandal explains that delivery may be later and uses an inexact alarm where supported.” Show creating an alarm/timer, exact-access denied explanation and Settings action, and an inexact notification delivery. |
| `USE_FULL_SCREEN_INTENT` | Removed from the release manifest as the lower-risk choice. Clock alerts use an ongoing high-priority notification with Stop/Snooze actions and a body tap to open the ringing activity; the app opens that activity when an alert fires while Jandal is visible. No full-screen-intent permission or system takeover is used. | No Play declaration required after removal. Show a ringing alert with the app in use and with full-screen access unavailable; verify the heads-up notification exposes Stop/Snooze and the body opens the ringing screen. |
| `PACKAGE_USAGE_STATS` | Special AppOps access is requested only when enabling Hey Jandal on the affected HONOR BKQ-N49 device, where stock camera/microphone contention requires detecting the camera entering foreground. Foreground events are processed in memory; unrelated usage events are discarded, and no usage history is stored or transmitted. | “On the affected HONOR BKQ-N49 only, Usage Access allows Hey Jandal to release microphone capture while the stock Camera records video. The feature is opt-in and has no usage-history collection.” Reviewer video must use the affected device, show the feature-specific Usage Access explanation and settings grant, then demonstrate camera/wake coexistence. |
| `WRITE_SETTINGS` | Used by the user-invoked display-brightness control; the feature directs the user to Android Modify system settings access before changing brightness. | “Modify system settings access is used only when the user chooses Jandal’s brightness control, to apply the requested screen brightness.” Show selecting brightness, the access explanation/settings screen, and the resulting brightness change. |
| `ACCESS_NOTIFICATION_POLICY` | Used by the user-invoked Do Not Disturb control; Android system settings grant access before Jandal changes interruption policy. | “Notification policy access is used only when the user chooses Jandal’s Do Not Disturb control, to apply the requested interruption-filter change.” Show selecting the DND control, the access explanation/settings screen, and the resulting DND state. |
| `CALL_PHONE` | Required only for the explicit hands-free `ACTION_CALL` skill after the user asks Jandal to place a call. Contact resolution is separately gated by Contacts access; the non-permission dialer fallback remains available. | “Phone permission is used only after the user explicitly asks Jandal to call a selected contact or number. Without it, Jandal offers the system dialer instead.” Show a user-requested call, permission request, and call confirmation; do not place a call without explicit user action. |

`WRITE_SETTINGS`, notification-policy access, Usage Access, and `CALL_PHONE` must not be requested at startup. Their settings/runtime request is feature-triggered as described above. The current release manifest still contains the permission declarations; the Play declaration must match the code and the reviewer flow.
