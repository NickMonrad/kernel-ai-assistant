Fixture: `clip.wav`, 16 kHz mono s16, sha256 `010e545272bfbe2a58f7f3633886edd7e35fd6ca96ca70a1b6bdcacd88ed6ffd` (full digest, checked against the file and against the header of `parity-expected.tsv`). Audio is not in Git.

Provenance limit: the clip was made once with `espeak-ng -v en-us -w clip.wav "<text>"` then `ffmpeg -i clip.wav -ar 16000 -ac 1 -sample_fmt s16 clip16.wav`. Those tool versions and the exact text were not recorded, so the WAV cannot be regenerated byte-for-byte. The SHA above is the only authority for identity. This is a parity check of the port on synthetic speech, not an accuracy measurement.
