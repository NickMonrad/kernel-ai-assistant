## Rule S4 (suggest-first), frozen

Input for each take and each size: the oracle's β 5 decision on the chosen slot. Code: `suggest_v4.py`
(`decide`), tests: `test_suggest_v4.py`. Output is one of:

- **PROMPT(name)**: "Did you mean <name>?" The text is not changed unless the user confirms.
- **SILENT(name)**: the heard text is already the top place (folded identity). The output is that place's
  canonical spelling (macrons and capitals). This never changes the place.
- **NONE**: the heard text is output unchanged.

Conditions, all required for PROMPT:

1. The oracle outcome is `accept`, or `suggest` with reason `word_count`.
2. The top entry is a rewritable (NZ) place. Competitor, impostor, `veto` (exact competitor, impostor or
   homograph hit) and `below_threshold` give NONE.
3. The margin passes (oracle margin 1.0, runner-up of any kind). Reason `margin` gives NONE.
4. The matched span passes the word-boundary check. Reason `boundary` gives NONE.
5. The heard text does not already equal the top place (otherwise SILENT).

Difference from the oracle's rewrite rule: the word-count check is not applied to prompts. Reason: a prompt
replaces nothing until confirmed, so the span-size check protects a rewrite that does not happen. This is
reported as a sensitivity count (prompts that failed word-count).

Silent place change is impossible by construction: SILENT only occurs when the folded heard text equals the top
place. The S4 safety measures below are therefore the prompts.

## Slots and decision point

- Primary slot: **hint** (caller slot-fill: the gate fires on the carrier, otherwise the whole utterance is the
  slot). It covers navigate, weather and bare-name lines.
- Secondary, reported, not pass/fail: `full` and `trigger`.
- Gate: v2 (as in v3).
- Size: M and L are both primary. Each must pass on its own.

## Pass criteria (binding; both sizes; primary slot hint)

Let a *wrong prompt* be a PROMPT whose name is not the gold place, on a gold line.

- **P1 (gold wrong prompts = 0).** Wrong prompts over the 36 gold lines = 0, and = 0 in each gold class (N = 12).
  Reported: per-class Wilson 95% upper bound (0/12 → 24.2%); pooled upper bound (0/36 → 9.6%).
- **P2 (gold silent wrong = 0).** SILENT with a name other than the gold place on a gold line = 0.
- **P3 (non-gold prompts = 0).** PROMPT on any non-gold line = 0, and = 0 in each of the six non-gold classes
  (N = 30 each; upper bound 11.3% per class). Pooled over 180 lines: upper bound 2.0%.
- **Pass** = P1, P2 and P3 all met at M and at L.

Information only (not pass/fail): offered-right rate (correct PROMPT or correct SILENT) per gold class, with
Wilson 95%; prompts by reason (word_count sensitivity); homograph-top prompts (NZ homograph names via
non-exact matches, which the v3 veto does not cover); gate fires per class; per-class prompt rates.

**Precondition for any switch-on discussion (not a pass criterion):** offered-right ≥ 50% at both sizes on the
36 gold lines. Switch-on remains an owner decision, and the setting ships off.

A single wrong prompt fails the test. A failure is recorded as is; no re-scoring with another rule, slot or
size is then used to pass. Any later rule change needs a new pre-registration version.

**Interpretation limit (stated before data):** zero observed errors in 180 non-gold and 36 gold lines does not
bound the error rate below about 10%. The pass means "no observed error in this set", not a safe rate.

## Recording protocol (v4)

1. One complete take per line, read as written, in the presentation order above. Rig: the owner's usual device
   and room, as in v3; the rig is logged in the private manifest. A result is labelled by its rig.
2. A re-take is allowed only before any decode output has been seen. Every re-take is logged and counted in the
   private manifest. Re-takes after output has been seen are not allowed and are reported as a protocol breach.
3. All 216 takes are in before any decode is run.
4. Audio: 16-bit mono 16 kHz, as in v3 (resample with ffmpeg; no other processing).
5. Decode: the v3 host harness (sizes M and L, tier `stream_c16r4`, chunk 100 ms, repeat 1,
   `dump_logits_dir`). Then `oracle.py --betas 5 --margin 1.0 --slot hint --gate v2` (defaults), then
   `suggest_v4.py --per-clip … --classes …` for the aggregates.
6. Recordings come from the owner's private Drive folder; nothing in the repository reads that folder.

## Not covered by v4

- **Competitor pre-filter.** Measured separately on existing data (see the README). It is not part of v4's
  pass. Before any on-device use, a pre-registered amendment (v4-a) must freeze K and the filter code, and the
  held-out dumps must show zero changed decisions against the unfiltered rule for the 216 takes at both sizes.
- **Device latency.** The S21 scoring p95 ≤ 50 ms criterion is a separate step-2 condition, not tested here.
- **Phone pipeline.** The takes are decoded through the host harness, not on the phone.
- **Parameter choice.** β 5, margin 1.0 and boundary on are frozen, not re-tuned on the new lines.

## Known risks (stated before audio)

- Gold N is 12 per class. The gold classes can show a wrong prompt only at rates above about 10% pooled.
- The homograph veto covers exact matches only. A foreign or AU name reached through a non-exact match can
  still prompt; this is measured as the homograph-top count and is not a pass criterion.
- Foreign coverage is cities of 15,000+ population (v3).
- The owner's microphone, room and rig differ from the synthetic sets. Synthetic results do not transfer.
- Each class has one speaker and one take per line; no repeat-take variance is measured.
